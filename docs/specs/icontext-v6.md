# iContext v6 operational contract

iDirectory, ThinkingSeed, MetricsThinking and iReadme remain independently executable. ContextControl coordinates them through a generated, versioned runtime. Python 3.10 or newer is required; only MetricsThinking requires Pydantic and PyYAML. No provider API is used for semantic authoring.

## Installation and entrypoints

From the ecosystem checkout, run `python ContextControl/icontext.py install --agents antigravity,codex`. Existing iContext installations are backed up; unrelated personal skills and rules are retained. Restart agent sessions after installation. On Windows the installer registers the user command directory for future terminals. The command is `icontext`; the compatibility entrypoints `python icontext.py`, `python FWengine.py`, `reconcile`, `update` and `capsule` remain available.

Antigravity discovers global bundles in `~/.gemini/config/skills`; Codex discovers them in `~/.agents/skills`. Repository bundles are installed in `.agents/skills`. `.context/toolchain.json` selects an installed runtime version; a missing pin fails explicitly rather than silently using a different version. `seed-master` is the portable skill name; `seedMaster` remains a natural-language compatibility alias. Repository maintainer adapters have distinct names to avoid collisions with global skills.

Bundles include scripts, references, templates and integrity manifests. Runtime source is maintained in iDirectory/src/core and ContextControl/src/core. Other distributions are generated by `python tools/build_runtime.py` from iDirectory; `--check` verifies their hashes. Generated directories have a pruning beacon and must not be edited manually.

## Read, update and repair

`icontext status` reads recorded state, not a live certification. `icontext pack <path>` supplies a bounded context view. `icontext audit` checks evidence and dependencies without writing. `sync --dry-run` plans work without creating files. `doctor` inspects installation and repository health; `doctor --fix` repairs installation and topology explicitly. JSON goes to stdout; `--verbose` expands diagnostic detail.

`icontext sync` updates the current project; `--all` selects the four registered ecosystem repositories. No subcommand displays help. Exit 0 means the operation succeeded, 1 means failure, and 3 means the current agent must author semantic changes. A failed required phase blocks dependent phases.

The update sequence is L0 evidence, SeedMaster, Metrics, README. `prepare seed|readme --json` supplies an input hash, changed evidence and affected sections. The current agent reads that evidence, preserves other sections, then runs `complete seed|readme --input-hash HASH`. Completion rejects changed inputs and invalid structure. Run `sync` again after each semantic stage. `index` and `metrics` remain standalone operations. `--full` forces content verification or complete audit recomputation.

The compact ThinkingSeed skill uses prepare hybrid / complete hybrid and does not require a master. Standalone metrics accepts --profile for the bundled archetype catalog and never requires another layer. Profile token budgets are enforced from context_policy.json; Tier 2 escalation follows architectural scope instead of a command name.

New README scaffolds require agent-specific authoring. The documentation engine only replaces its managed telemetry block in an existing README. Performance and quality values without evidence remain unmeasured. `--update-golden` is a separate, explicit acceptance operation.

## Incremental evidence and continuity

The orientation cache in `.context/orientation_cache.json` is compiled only during explicit index/sync operations. Hot queries avoid importing the complete engine, verify inherited pruning and selected file metadata, and identify recorded generations. JSON command output uses UTF-8 on Windows.

The persistent inventory tracks file content hashes, nanosecond file metadata, analyzer version, policy, public contracts and imports. Ordinary updates reuse unchanged records. Full verification rereads contents, including same-size changes with restored timestamps. Additions, deletions, renames and changes outside Git commits are included. Beacon and ignore pruning happens before traversal. Generated state and runtime distributions are excluded from source inputs.

File discovery still costs metadata operations across the governed set; incremental processing reduces content reads and AST parsing to affected files. It does not promise total O(delta) filesystem discovery. Criteria reuse includes rule code, profiles and the evidence attributes a rule consumes; unknown helper dependencies invalidate conservatively. An unchanged audit reuses validated artifacts without changing their timestamps.

Each layer owns a sidecar in `.context/layers`. Bus aggregation uses a repository OS lock and atomic replacement. Missing information is unknown, and legacy records remain explicitly unverified. A successful aggregate write does not certify semantic quality.

Use `icontext checkpoint --set --session-id TASK --objective TEXT --constraint TEXT --next TEXT` to record a bounded session. Other agents can resume it with `checkpoint --show --session-id TASK`. Sessions preserve their own objective, constraints, evidence hash, decisions and next action. A default checkpoint remains for compatibility; completed sessions do not authorize new work.

## Measurements and acceptance

`icontext benchmark --target PROJECT --json` measures in-process and process query p50/p95, full versus incremental inventory time and content reads. It is read-only. Estimates use a declared heuristic, not provider billing or hidden prompt overhead. The FPAI score is an auxiliary structural indicator; duplication is based on exact content and unmeasured distortion is labeled accordingly.

Acceptance includes no-write queries, a no-change synchronization, content-backed AST invalidation, working-tree changes, inherited pruning, concurrent publishers, independent runtime copies, equivalent installed bundles and isolated sessions. Live model task success and real provider token accounting require separately observed host sessions; filesystem and CLI tests must never be presented as those measurements.

## Upgrade and retained history

Version 6 retains legacy CLI aliases for this major release and validates version 5 artifacts through compatibility schema branches. Older rule files and skill workflows are retained in docs/specs as historical references. They are not default context. Existing work is preserved; update semantic documentation in its existing sections instead of replacing whole files.
